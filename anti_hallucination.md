clear# Anti-hallucination controls in `funda_agent_exp.py`

## Executive summary

The agent has two different output paths:

1. Trusted chart artifacts are generated by Python from database/API data, kept in
   out-of-band `AgentState` fields, and inserted into the final answer by runtime code.
2. The LLM is allowed to explain textual statistics, but runtime code controls which
   chart payloads can reach the user and removes or rejects unsafe/model-invented chart
   blocks.

For trusted PCA and word-cloud artifacts, chart JSON, coordinates, word counts and labels
do not depend on the model reproducing tool output correctly; PCA also supplies tool-derived
chart follow-up suggestions. Generic chart values and additional model suggestions remain
model-authored. These controls do **not**
make all prose numerically hallucination-proof: PCA/statistical explanation text is still
model-authored unless the caller only requests a word cloud.

This is supporting explanation of the concrete patterns, not a second workflow or location
map. Resolve the named symbols in `funda_agent_exp.py` before relying on an implementation
detail; `PROTOCOL.md` and the FLOW documents govern diagnosis, correction and verification.

## End-to-end propagation map

### PCA

`run_survey_stats()` → `_prepare_stats_response()` → internal
`_PCA_TOOL_RESULT_PREFIX` envelope → `call_tool()` →
`state["pca_chart_artifacts"]` → `call_model()` → `_assemble_pca_final()` → final
`AIMessage`.

The model sees the formatted statistical text, but does not see the trusted chart
envelope as model-visible tool text. The final chart artifact is appended from state.

### Word cloud

`generate_word_cloud()` → `_fetch_word_cloud_source()` →
`_build_word_cloud_artifact()` → internal `_WORD_CLOUD_ARTIFACT_PREFIX` envelope →
`call_tool()` → `word_cloud_artifact`/`word_cloud_intro` state fields → `call_model()`
short-circuit → final `AIMessage`.

The final word-cloud response is assembled without another LLM call.

### Generic/model-authored charts

If the model emits a `gpi-chart` block without a trusted PCA artifact,
`_sanitize_model_chart_blocks()` validates it. Valid bounded JSON chart blocks survive;
invalid or unsafe blocks are removed and replaced with a user-facing rebuild message.
This is validation and containment, not deterministic grounding of the chart’s numbers.

## Primary deterministic controls

### `_build_pca_chart()`

Builds the trusted PCA biplot payload from normalized API data. It selects PC axes,
validates finite coordinates, applies the 2D fallback when a requested PC3 cannot be
used, enforces point limits, creates titles/subtitles/metadata, and serializes the
artifact as `gpi-chart` JSON.

The LLM cannot invent or alter PCA coordinates, variance labels, product labels, or
attribute labels in this artifact. It can only explain the statistics supplied as text;
the runtime later appends this independently built payload.

### `_normalize_pca_analysis()`

Validates and normalizes the API’s PCA response. It extracts attributes, products,
principal components, product scores, loadings, respondent count, and analysis N. It
also fills missing PC coordinates from the API’s supplementary score/loading structures.

This creates the stable input contract consumed by `_build_pca_chart()` and prevents a
malformed API response from becoming a fabricated chart. It is a validation/normalization
stage, not a final-output function by itself.

### `_pca_points()`

Converts PCA rows into chart points and rejects missing labels or non-finite coordinates.
It prevents incomplete or invalid coordinates from entering a trusted chart artifact.

### `_finite_float()`

Accepts only real, finite numeric values and rejects booleans, non-numbers, NaN, and
infinity. It is used by PCA and generic-chart validation so invalid coordinates or chart
values cannot be propagated as trusted numeric output.

### `_prepare_stats_response()`

Deterministically formats ANOVA, Tukey, Pearson, Spearman, chi-square, and PCA results.
For PCA it invokes `_normalize_pca_analysis()` and `_build_pca_chart()`, returns the
formatted text separately from a list of trusted chart artifacts, and records explicit
unavailability/errors rather than silently filling gaps.

It also emits a deterministic warning when split correlation tests all miss alpha,
preventing the model from treating that result as proof that no relationship exists.

The formatted text is still shown to the LLM, so the model may paraphrase or omit it.
The chart artifact returned in the second tuple element remains protected and is later
assembled by `_assemble_pca_final()`.

### `_format_pca_analysis()`

Renders PCA components, loadings, product scores, retention data, diagnostics, warnings,
and chart status into deterministic tool text. It explicitly tells the model not to
reproduce chart JSON.

This reduces ambiguity and supplies faithful source material, but it is only a partial
anti-hallucination control because the textual content remains in the model’s context.

### `_assemble_pca_final()`

The PCA final-response compositor:

- removes every model-emitted `gpi-chart` block;
- keeps the model’s prose;
- appends each trusted artifact from `pca_chart_artifacts` unchanged;
- adds tool-derived 2D/3D follow-up suggestions;
- includes model suggestions only after filtering/deduplicating them and caps the total
  at five.

Consequently, the model cannot replace trusted PCA chart JSON with a hallucinated chart,
change its values, or emit both a trusted and conflicting model chart. The explanation
can still be model-authored.

### `_split_trailing_suggestions()`

Separates the model’s prose from trailing `{{...}}` suggestion lines while preserving
their order. `_assemble_pca_final()` uses it before discarding model chart blocks and
rebuilding the final suggestion list, so suggestion markup cannot be accidentally mixed
into trusted chart prose or payloads.

### `_build_word_cloud_artifact()`

Aggregates the exact fetched open-ended answers deterministically. It deduplicates terms
within each answer component, filters emails/URLs/stop words/subject terms, optionally
groups by product, sorts terms deterministically, applies the maximum-term limit, and
serializes the final word-cloud payload and introduction.

The word counts, grouping, question metadata, answer count, and chart JSON therefore do
not come from an LLM and cannot be fabricated by it.

### `generate_word_cloud()`

Validates the question id and scope, calls the source fetcher and deterministic builder,
and returns the result inside `_WORD_CLOUD_ARTIFACT_PREFIX`. Errors fail closed with a
user-facing unavailable result rather than exposing or inventing data.

### `call_tool()` artifact extraction

Although it is a graph node rather than a private helper, this is the key propagation
boundary. It parses PCA and word-cloud internal envelopes, validates their required
fields, removes the artifact envelope from the model-visible `ToolMessage`, and stores
trusted payloads in state.

For PCA, only formatted text is sent in the tool message while chart objects are added
to `pca_chart_artifacts`. For word clouds, only a short deterministic readiness message
is sent to the model while the complete artifact and introduction are stored in state.
Malformed envelopes are rejected and replaced with an unavailable/error message.

### `call_model()` trusted-output handling

This is the final dispatch boundary:

- If `word_cloud_artifact` exists, it immediately returns `word_cloud_intro` plus the
  trusted artifact and increments the step count. No LLM invocation occurs.
- If PCA artifacts exist after an LLM response, it replaces the response content with
  `_assemble_pca_final(response_text, pca_artifacts)`.
- If the model attempts to emit a word-cloud block without using the tool, it removes the
  block and returns `UNTRUSTED_WORD_CLOUD_BLOCK` instead.
- If generic chart blocks are emitted, it sends them through
  `_sanitize_model_chart_blocks()`.

This ensures the frontend receives tool-owned word-cloud/PCA chart data only through the
runtime-controlled paths.

## Supporting deterministic safeguards

### `_sanitize_model_chart_blocks()`

Validates model-authored generic charts before they reach the frontend. It requires a
supported chart type/version, rejects script-like content, requires data, enforces point
and series limits, and checks the correct payload shape for category, scatter, and
heatmap charts. Invalid blocks are withheld.

This prevents malformed, unsafe, or oversized chart payloads. It does not verify that
the model’s accepted numeric values match a database/tool result, so generic charts are
contained rather than fully hallucination-proof.

### `_safe_chart_label()`

Normalizes chart labels by removing line breaks and braces and supplying a fallback. It
prevents labels from injecting formatting/suggestion syntax into trusted chart metadata.

### `_filter_chart_suggestions()`

Filters trailing `{{...}}` suggestions to chart-related requests. It is a defensive
formatter, but it is currently not called by the active final-response path;
`_assemble_pca_final()` performs its own stricter suggestion handling.

### `_word_cloud_display_text()`

Converts the source question prompt to one line and neutralizes `{{...}}` sequences.
This prevents survey text from becoming frontend suggestion widgets when inserted into
the deterministic word-cloud title/introduction.

### `_word_cloud_tokens()`

Deterministically removes email/URL material, normalizes Unicode, keeps letter tokens,
and excludes short, stop, and subject terms. This prevents sensitive/noisy source text
and generic question vocabulary from distorting the generated word cloud.

### `_fetch_word_cloud_source()`

Reads the authorized question and answer rows inside a read-only transaction with a
statement timeout. It validates existence, survey scope, and open-ended question type
before returning source data to the builder. This grounds the artifact in an authorized
tool/database result rather than model-supplied text.

### `_rank_word_cloud_terms()`

Sorts terms by descending count and then alphabetically, applies the term limit, and
returns stable `{label, count}` records. Ordering and counts are therefore reproducible.

### `_format_stats_response()`

Compatibility wrapper that returns only the deterministic textual portion of
`_prepare_stats_response()`. It does not preserve artifacts and is not the protected
graph path used by the current PCA envelope; callers needing trusted charts use
`_prepare_stats_response()` directly.

## What remains LLM-dependent

- Statistical prose and conclusions based on the text from `_prepare_stats_response()`.
- Product/question interpretation and selection of tools/arguments.
- Generic charts that pass `_sanitize_model_chart_blocks()`; they are structurally safe
  but their values are still model-authored.
- Model-provided non-chart claims and suggestions, subject to prompt rules.

The strongest architectural guarantee is therefore narrow and deliberate: PCA and word-
cloud chart artifacts are generated, stored, and emitted by deterministic runtime code;
the LLM is not trusted to reproduce those payloads. Word clouds additionally bypass the
final LLM turn entirely, while PCA retains model-authored explanatory prose and replaces
only the chart-bearing portion with trusted output.
